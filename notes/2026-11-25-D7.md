## 二、sudo 规则验证的关键认识

两条测试命令，结果完全不同：

```
sudo systemctl restart nginx    → 放行，systemctl 报 Unit not found
sudo systemctl restart bginx    → Sorry, user tom is not allowed...
sudo systemctl stop nginx       → Sorry, user tom is not allowed...
```

三个认识：

1. **放行时 sudo 不吭声**，是 systemctl 自己跑起来才报错；**拒绝时 sudo 直接拦**，systemctl 根本没运行。看报错里有没有 "Sorry, user ... is not allowed" 就能区分。
2. **规则里参数写死才锁得住**。`restart nginx` 三个词是一个整体，换个包名、换个动作都放行不了。
3. **必须在目标用户身份下测**。root 自己有一条 `(ALL) ALL`，root 跑 sudo 永远放行，测不出 tom 的规则。
4. sudo 的流程是**先验密码、再判权限**。密码连错三次只会报 `3 incorrect password attempts`，根本走不到权限判断。

小坑：拒绝信息里显示 `/bin/systemctl`，而规则里写的是 `/usr/bin/systemctl`，照样匹配 —— Rocky 9 里 `/bin` 是 `/usr/bin` 的软链（usrmerge），sudo 按文件本身认，不按路径字符串认。

## 三、软件仓库：一个仓库到底需要什么

> **`.repo` 文件只是告诉 dnf "去哪找"，真正的东西得在那个目录里，而且依赖要能补齐。**

三件套：

1. **一个目录**，里面躺着 `.rpm`
2. **`repodata/` 索引**（`createrepo_c` 生成）—— dnf **只读索引**，不一个个翻 rpm
3. **`/etc/yum.repos.d/*.repo`** —— `[仓库id]`、`name=`、`baseurl=`、`enabled=`、`gpgcheck=`

`.repo` 五个字段：

| 字段 | 含义 |
|---|---|
| `[local-repo]` | 仓库 id，命令行里 `--enablerepo=` 用的就是它 |
| `name=` | 给人看的描述 |
| `baseurl=file:///opt/localrepo` | 包所在位置（本地用 file://，网络用 http://） |
| `enabled=1` | 1 启用 / 0 停用。停用不用删文件 |
| `gpgcheck=0` | 装包时验不验签名。自己拷的包没签名，写 1 装不上 |

**没写进 `/etc/yum.repos.d/` 的目录，dnf 根本不知道它存在。**

## 四、今天踩的仓库报错（每个都能对应一个知识点）

| 报错 | 原因 |
|---|---|
| `Couldn't open file /opt/mini/repo/repodata/repomd.xml` | `baseurl` 写错，把 `/opt/mini-repo` 写成了 `/opt/mini/repo` |
| `nothing provides libacl.so.1(ACL_1.3) needed by acl-2.4.0` | 仓库里缺依赖包。仓库必须能凑齐依赖，不是一个包的问题 |
| 加了包但 dnf 还是看不见 | 没重跑 `createrepo_c --update`。索引才是 dnf 读的东西 |
| 索引更新了还是不行 | 没 `dnf clean all`。dnf 缓存着旧的包列表 |
| `Installed package acl-2.3.1-4 (from anaconda) not available` | `reinstall` 只认同版本；版本不同要用 `upgrade` |

**完整流程**：拷包进目录 → `createrepo_c --update` → `dnf clean all` → `dnf install`

## 五、EPEL 为什么在这台机器上装不上

`epel-release` 只是往 `/etc/yum.repos.d/` 放一个 `epel.repo`，里面的 `baseurl` 指向**互联网**。网络源全关，所以连不上。

要装 EPEL 的包：在能上网的机器上 `dnf download --resolve htop`（`--resolve` 连依赖一起下）→ 搬进 `/opt/localrepo` → `createrepo_c --update` → `dnf clean all` → 再 install。

## 六、Shell 脚本基础（D7）

### 三个必须知道的写法

| 写法 | 含义 |
|---|---|
| `#!/bin/bash` | 声明用哪个解释器。不写也能跑，但会按 `sh` 的语法解释，bash 专有写法（`[[ ]]`）会挂 |
| `$名字` | 取**变量的值** |
| `$(命令)` | 把命令跑一遍，拿它的**输出**替换这段文字（命令替换） |

`$SRC` 和 `$(date +%Y)` 的区别就是：一个是变量里存的东西，一个是命令跑出来的结果。老写法反引号 `` `date` `` 等价，别用。

变量赋值**等号两边不能有空格**。`SRC = /data/share` 会被拆成"命令 SRC + 参数 = 和 /data/share"，报 `SRC: command not found`。

### `>` 和 `>>`

- `>` 覆盖，每次清空重写
- `>>` 追加到末尾，文件不存在就创建

日志必须用 `>>`。

### 函数

```bash
log() {
    echo "[$(date +%F_%T)] $1" >> $LOG
}
```

`log()` 定义函数，`{ }` 里是它做的事，`$1` 是调用时传进来的第一个参数。调用写 `log "消息"`，不加 `./`。

### `tar -czf`

- `c` = create 创建归档
- `z` = gzip 压缩
- `f` = file，紧跟其后的参数是文件名

`f` 必须放最后一个，否则 tar 把后面的字母当文件名。`t` 是 list，只看不解；`x` 是解包。

看到 `tar: Removing leading '/' from member names` 不是错误 —— tar 把 `/data/share` 存成 `data/share`，免得解包时按绝对路径覆盖系统文件。

## 七、今天的操作事故（都是老坑）

1. **`su -tom` 又缺空格** —— 第二次犯了。`-t -o -m` 被当成选项，报 invalid option。
2. **`mkdir -p /root/d7/backup`** —— 本来要建 `/root/d7` 和 `/backup` 两个，少一个空格变成一个嵌套目录，导致后来 `tar` 报 `Cannot open: No such file or directory`。
3. **`ECHO` 大写** —— bash 命令区分大小写，`command not found`。而且它排在 `tar` 后面，出现"活干了一半"的假成功。
4. **`opt/localrepo/...` 少开头的 `/`** —— 相对路径从当前目录找。cp 直接报 `cannot stat`。
5. **`--enablerepo-mini`** —— 选项和值之间用 `=`，用 `-` 会被当成一个不存在的选项名。
