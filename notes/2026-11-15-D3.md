# D3 进程与 systemd（2026-11-15）

1. 如何将自己脚本的运行放到后台。

   在终端里直接运行时，父进程是 bash，所以会占用终端。交给 systemd 后就不占终端了，因为是 systemd 帮忙运行的，此时 PPID 为 1（1 号进程就是 systemd）。

   脚本不放 /root，是因为 SELinux 的访问限制，systemd 无法执行 /root 下的脚本，所以放到 /usr/local/bin。

2. simple和forking的区别

   simple：systemd 默认的方式，启动的那个进程会一直运行，启动了就算成功。

   forking：用于老服务的一种特殊处理，程序会先复制出一个分身到后台，然后主程序退出，systemd 等主程序退出后才认定启动完成。

   实验：把 hello 写成 Type=forking 后 restart，一直卡在启动中，90 秒后报启动超时。因为 hello.sh 里并没有复制和退出的动作，systemd 等不到它退出。

3. systemctl 里start 和enable的区别

   start 管现在：立刻启动，重启后就不管了。enable 管以后开机：开机时自动启动，现在不管。两者互不影响，通常两条都要执行。

   enable 其实是建立了一个软链接：在 /etc/systemd/system/multi-user.target.wants/ 目录里，指向 hello.service。系统开机到 multi-user.target 阶段时，会把这个目录里链接指向的服务都启动。目录名里的 multi-user.target 就是 [Install] 里 WantedBy= 写的那个。

   验证：reboot 后用 systemctl status hello，Loaded 那行显示 enabled，Active 是 running，Main PID 很小（798），说明是开机时启动的。

4. .service的格式

   文件位置：/etc/systemd/system/hello.service，文件名决定服务名（hello）。最终内容：

   ```ini
   [Service]
   ExecStart=/usr/local/bin/hello.sh
   Restart=on-failure

   [Install]
   WantedBy=multi-user.target
   ```

   - [Service]：这一段写服务怎么跑。
   - ExecStart：启动时执行哪个程序，必须写完整路径。
   - Restart=on-failure：服务异常退出（比如被 kill -9）就自动重启；手动 systemctl stop 不会触发。验证方法：kill -9 掉 Main PID，再看 status，仍是 running，PID 变了。
   - [Install]：这一段只在 enable 时用到。没有这一段，status 里显示 static，enable 会失败。
   - WantedBy=multi-user.target：开机到"正常多用户模式"这个阶段时，把我也启动。
   - 没写 Type，默认就是 simple。
   - 改完 .service 文件后要先 systemctl daemon-reload，systemd 才会重新读。

5. 今天卡住的地方

   - 直接运行 /root/hello.sh 报 Permission denied：用 ls -l 看到权限是 rw-r--r--，没有 x，chmod 744 后就能运行了。
   - 以为写 Type=forking 才能让服务在后台跑。其实占不占终端看的是谁启动的它，Type 只是告诉 systemd 这个程序启动后，第一个进程会不会退出。

6. 服务以什么身份运行

   去执行脚本的是 systemd（1 号进程，root 身份），systemctl 只是捎话的命令。unit 里没写 User= 时，服务默认以 root 身份运行；加 User=tom 就以 tom 身份运行。正式环境一般用权限小的专门用户跑服务（比如 nginx、mysql 用户）。

   查看身份：ps -o user,pid,ppid,cmd -C hello.sh

7. SELinux

   SELinux 是 rwx 之外的另一道安全检查。它按规则给进程和文件贴标签，再按规则表核对"这类程序能不能碰这类文件"，root 也要遵守。

   - rwx 看你是谁；SELinux 看你是哪类程序、要碰哪类文件。
   - 先查 rwx，通过了再查 SELinux，两道都过才能访问。
   - getenforce：查看状态，Enforcing 表示开着并且在拦。
   - ls -Z 看文件标签，ps -eZ 看进程标签。
   - systemd 是 root，但执行不了 /root/hello.sh：标签是 admin_home_t，而 /usr/local/bin/hello.sh 的标签是 bin_t，systemd 只能执行 bin_t 的文件。
   - 别遇到问题就关 SELinux，正确做法是看日志、改标签。

   排查 Permission denied 的顺序：
   1. 先 ls -l 看 rwx（今天手动运行时缺 x，chmod 解决）
   2. rwx 没问题还被拒，再 ls -Z 看 SELinux 标签（今天 systemd 执行 /root 下的脚本就是这种）
