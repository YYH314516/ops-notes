# D4 磁盘与 LVM（2026-11-16）

1. 新硬盘怎么变成能用的空间

   完整流程：加盘 → fdisk 分区 → pvcreate → vgcreate → lvcreate → mkfs 格式化 → mount 挂载 → 写 fstab 开机自动挂载。

   今天的最终结构：

   ```
   sda1 (5G) ─┐
              ├─ PV ─→ vgdata (10G) ─→ lvdata (10G) ─→ xfs ─→ /data
   sda2 (5G) ─┘
   ```

2. PV / VG / LV 三层关系

   - fdisk：把硬盘切成分区（sda1、sda2），这一步不是 LVM。
   - PV（物理卷）：给分区打上标记，让它归 LVM 管。整块盘也能直接做 PV。
   - VG（卷组）：把一个或多个 PV 合成一个池子，统一管理。
   - LV（逻辑卷）：从 VG 池子里划出一块来用，相当于一块虚拟硬盘。它是**设备**不是目录（`cd /vgdata` 进不去），路径是 `/dev/池子名/LV名`，要先格式化成文件系统、再挂载到目录上才能放文件。

   一句话：fdisk 切，PV 登记，VG 合并，LV 分出来用。

   为什么要用 LVM：普通分区大小是定死的；LVM 的 LV 不够了可以从 VG 再划，VG 不够了可以再加 PV，扩容不用停机。

3. 分区（fdisk）

   - `lsblk`：看所有盘和分区；`fdisk -l /dev/sda`：只看不改。
   - `fdisk /dev/sda` 进入后一问一答：`n` 新建 → 回车用默认 → `+5G` 定大小 → `t` 改类型 → `8e`（Linux LVM）→ `p` 先看 → `w` 写入。
   - 敲 `w` 之前什么都不会写进硬盘，敲错就 `q` 退出。
   - 盘上有分区正在用时，fdisk 会警告"This disk is currently in use"。只在空白处新建分区没问题，但不能改、不能删正在用的分区。

4. 建 PV / VG / LV

   ```bash
   pvcreate /dev/sda1                 # 登记成 PV
   vgcreate vgdata /dev/sda1          # 建池子 vgdata
   lvcreate -n lvdata -L 3G vgdata    # 从池子里划 3G，起名 lvdata
   pvs / vgs / lvs                    # 分别查看三层
   ```

   - 刚 pvcreate 完，pvs 里 VG 栏是空的，说明还没进任何池子。
   - LVM 按 4M 一块分配空间，这一块叫 extent（PE），3G = 768 块。
   - Attr 栏：三条命令的 Attr 含义各不相同。lvs 里只看两位：`a` = active（激活），`o` = open（正在被使用，比如已挂载）。

5. 格式化和挂载

   ```bash
   mkfs.xfs /dev/vgdata/lvdata        # 建 xfs 文件系统，会清空设备，路径一定看清
   blkid /dev/vgdata/lvdata           # 看文件系统类型和 UUID
   mkdir /data
   mount /dev/vgdata/lvdata /data     # 先写设备，再写目录
   df -h /data                        # 看文件系统大小和挂载点
   ```

   - 格式化就像给毛坯房铺地板，铺好才能放东西；挂载就是把设备接到某个目录上，进目录就等于进设备。
   - 刚建好的空文件系统 df 显示已用 54M，是 xfs 自己的记账空间。
   - 卸载是 `umount`（没有 n）。人在挂载目录里时卸载会报 target is busy，要先 `cd /`。

6. 开机自动挂载（/etc/fstab）

   mount 是临时的，重启就没了。要写进 /etc/fstab：

   ```
   UUID=2b783d84-63e1-44c7-b558-286bf76a22c3  /data  xfs  defaults  0 0
   ```

   六栏：设备（用 UUID）、挂载目录、文件系统类型、挂载选项、dump 备份（0）、开机检查（xfs 填 0）。

   fstab 写错可能开不了机，所以**写完先测试再重启**：

   ```bash
   umount /data
   mount -a                  # 按 fstab 挂一遍，没输出才对
   findmnt --verify          # 检查 fstab 语法
   systemctl daemon-reload   # 改了 fstab 要刷新，跟改 .service 一样
   ```

   systemd 会把 fstab 每一行翻译成一个挂载任务，/data 对应 `data.mount`，可以 `systemctl status data.mount` 查看。

7. 在线扩容（不卸载、不停机）

   扩容永远是两层：**先扩 LV（设备），再扩文件系统**。

   ```bash
   lvextend -L +1G /dev/vgdata/lvdata   # 扩设备：3G → 4G
   xfs_growfs /data                     # 扩文件系统，参数是挂载目录
   ```

   实验：只敲 lvextend 后，lvs 显示 4G，df 还是 3G。因为 xfs 是按 3G 格式化的，它还只管 3G，要 xfs_growfs 让它长满新空间。

   池子不够时，再加一个 PV：

   ```bash
   pvcreate /dev/sda2
   vgextend vgdata /dev/sda2                       # 把新 PV 倒进池子
   lvextend -r -l +100%FREE /dev/vgdata/lvdata     # 一步到位
   ```

   - `-r`：扩完 LV 顺手扩文件系统，等于自动执行 xfs_growfs。
   - 大写 `-L` 跟具体大小（+1G）；小写 `-l` 跟 extent 数或百分比，`+100%FREE` 就是把池子剩下的全加上。
   - `-L +1G` 是"再加 1G"，`-L 4G` 是"变成 4G"。

   最后 /data 从 3G → 4G → 10G，全程没卸载，文件内容一直在。

8. 面试常问

   - xfs 只能扩不能缩，要缩只能备份、删掉重建、再恢复；ext4 能缩但必须先卸载。
   - 扩容命令：xfs 用 `xfs_growfs 挂载点`，ext4 用 `resize2fs 设备路径`。

9. 今天卡住的地方

   - **重启后盘名对调了**：数据盘从 sdb 变成 sda，系统盘从 sda 变成 sdb。我按旧名字 `fdisk /dev/sdb` 进了系统盘，看到"盘在使用"和"All space for primary partitions is in use"，没敲 w，没出事。
     - sda、sdb 是开机时按发现顺序临时分配的名字，不固定。
     - 所以 fstab 要用 UUID：UUID 写在文件系统里，跟着数据走。LVM 也认盘上的标记，不怕改名。
     - **以后动任何盘（fdisk、mkfs、pvcreate）之前，先 lsblk 按大小和挂载点认准是哪块。**
   - 以为 LV 是"逻辑目录"：其实是设备，要格式化 + 挂载才有目录。
   - 以为 lvextend 扩的是 VG：其实扩的是 LV，VG 反而被划走了空间；扩 VG 用 vgextend。
   - 拼写错误：`fidisk`、`/dev/vgata`。看到 command not found / does not exist，先查拼写。
