# D6 软件包与源（2026-11-18）

今天只做了一件事：**自己造一个本地软件仓库，把网络源全关掉，只从它装 MySQL。**
第三方源（EPEL）没做，留到下一次。

## 0. 开场冷启动（重做 D5）

- `ss -tlnp | grep :8000` → `LISTEN 0 5 0.0.0.0:8000 ... users:(("python3",pid=7744,fd=3))`
  - `0.0.0.0:8000` = 监听**所有网卡**，本机能连、局域网也能连（防火墙放行的话）
  - `users:(("python3",pid=7744,...))` 是 `-p` 的功劳，**只有 `-p` 能告诉你"是谁"**
  - 只想本机连就 `--bind 127.0.0.1`。数据库绑 `0.0.0.0` 是事故，不是配置。
- 临时 HTTP 服务：`python3 -m http.server 8000`
  - `-m` = 运行一个模块（Python 自带，不用装），把**当前目录**当网站根目录
  - 敲完屏幕"卡住不动"就是正常，它在工作，占着这个终端。**同一标签页 Ctrl+C 或关掉 = 服务消失**（D5 栽过）
- 抓包抓到了一次完整的 **11 包**：三次握手 → HTTP 请求/响应 → 挥手。

**抓包读数（这次亲手拍到的）**

```
[S]   seq 1876356242                      客户端敲门
[S.]  seq 4259780779, ack 1876356243      一个包干两件事：同意 + 确认你的号
[.]   ack 1                               纯确认，连接建立
[P.]  seq 1:79  ack 1     length 78       客户端发 GET，78 字节
[P.]  seq 1:156 ack 79    length 155      服务端响应头
[P.]  seq 156:987 ack 79  length 831      服务端响应正文
[F.]  seq 987 ack 79                      服务端先说要关
[F.]  seq 79  ack 988                     客户端同意 + 自己也要关
[.]   ack 80                              确认
```

- 握手之后 tcpdump 自动切成**相对序号**（从 0 数），`ack 79` = 下一个期望的字节。要绝对号加 `-S`。
- 服务端两次响应里 `ack` 一直是 79 没变 —— 客户端发完请求就没再说话，这就是"累积确认报的是**下一个期望的字节**"。
- `151 + 831 → 987`，验算对得上。
- 挥手这里只有 **3 个包**，不是 4 个：客户端的 ACK 和它自己的 FIN 合成了第 11 行（`[F.]`）。
- `python3 -m http.server` 一个请求一条连接，回完就 FIN。**真的 HTTP/1.1 默认长连接**，D8 部署 Nginx 时会看到抓包里没有这么勤的 FIN。

## 1. 三个东西的关系（今天的核心概念）

| 东西 | 是什么 | 类比 |
|---|---|---|
| `.rpm` | 一个软件包，压成单文件 | 一个包裹 |
| 仓库 repo | 一堆 rpm + 一份**清单**（repodata） | 仓库 + 货物目录 |
| `dnf` | 读清单、算依赖、下载、调 rpm 装 | 仓库管理员 |

**`dnf` 是"会看清单、会算依赖"的 rpm 前端，最后真正把文件写进系统的还是 rpm。**

- `rpm -ivh x.rpm` 也能装，但**不管依赖**——缺什么报什么，自己找。
- `yum` 和 `dnf` 是同一个东西，Rocky 9 里 `yum` 是指向 dnf 的软链接，老教程照抄能用。

## 2. 造本地源的完整流程

```bash
mkdir -p /opt/localrepo                    # -p：父目录不存在一起建，重复敲不报错
dnf install -y dnf-plugins-core            # 提供 dnf download 子命令
dnf install -y createrepo_c                # 生成索引

dnf download --resolve --alldeps --downloaddir=/opt/localrepo mysql-server
createrepo_c /opt/localrepo                # 第一次全量
```

`dnf download` 那两个参数：
- `--resolve` 把依赖的包一起下
- `--alldeps` 依赖继续递归往下，不止一层

结果：199 个包，99M。`createrepo_c` 输出 `Directory walk done - 199 packages`，**这个数字要跟目录里的文件数对得上**，对不上说明有包被忽略（不是合法 rpm）。

生成的东西在 `/opt/localrepo/repodata/` 里，总入口是 `repomd.xml` —— dnf 一读它就知道有哪些包、依赖是什么、校验和多少。

## 3. `.repo` 文件

`dnf` 启动时读 `/etc/yum.repos.d/` 下所有 `*.repo`。格式是 INI，一个方括号段 = 一个仓库。

```ini
[local-repo]
name=Local Rocky Packages
baseurl=file:///opt/localrepo
enabled=1
gpgcheck=0
```

| 行 | 作用 |
|---|---|
| `[local-repo]` | 仓库 ID，全系统唯一，`--enablerepo=` 用这个名字 |
| `name=` | 描述，`repolist` 里显示的就是它 |
| `baseurl=` | 仓库在哪。`file://` 本机，`http://` 网络 |
| `enabled=1` | 默认启用 |
| `gpgcheck=0` | 不校验签名。**生产必须 1**，否则谁往目录丢个包都能装进去 |

**`file:///opt/localrepo` 三个斜杠**：`file://` 是协议，后面跟绝对路径 `/opt/localrepo`。两个斜杠（`file://opt/localrepo`）会被当成主机名 `opt`。

写文件不用 vi，用 heredoc：

```bash
cat > /etc/yum.repos.d/local.repo << 'EOF'
[local-repo]
name=Local Rocky Packages
baseurl=file:///opt/localrepo
enabled=1
gpgcheck=0
EOF
```

- `<< 'EOF'` 的**单引号要紧**，加了就是原样写入、不做变量替换
- 结尾 `EOF` 必须**顶格单独一行**
- 写完屏幕不回显，`cat` 一下验

验证：`dnf repolist` 里出现 `local-repo` 那行才算认了。

## 4. 只用本地源装 MySQL

```bash
dnf --disablerepo='*' --enablerepo=local-repo install mysql-server
```

- `--disablerepo='*'` 所有源关掉。`'*'` **必须加引号**，否则 shell 把它展开成当前目录的文件名
- `--enablerepo=local-repo` 单独打开本地源
- **这两个参数必须写在 `install` 前面**。写在后面 dnf 会当成包名解析，报 `no package matched`
- 最后 `--assumeno` = 算完就退别装，用来**预演**；确认没问题再换成 `-y` 真装

预演通过的样子：`Dependencies resolved.` + 包列表里 `Repository` 列**全是 `local-repo`** + `Operation aborted.`（因为答了 n）。

## 5. 今天踩的坑（错题本重点）

### 坑 1：`dnf download` 和 `dnf install` 的依赖判定标准不一样

这是今天**最大的一个坑**，连着报了三次错，全是同一个病根。

`dnf download --resolve --alldeps` 只按包上写的**硬依赖**往下追，而且**不看这台机器现在装了什么**。`dnf install` 是**按机器的实际状态**算：条件依赖要不要成立、版本锁会不会打架，它全看。

所以出现"下载时看着齐了，安装时说缺"。

具体三次：

**第一次**：`requires (mysql-selinux if selinux-policy-targeted)`
- 这是**条件依赖**：如果装了 targeted 策略，就必须要 `mysql-selinux`
- 本机 `selinux-policy-targeted` 本来就装着（Rocky 默认），条件成立，成了硬需求
- `dnf download` 把 `(A if B)` 当可选，没下
- 顺带一提：`mysql-selinux` 会把 SELinux 策略从 38.1.75 升到 38.1.86，连带升级是正常的

**第二次**：`cannot install both audit-libs-3.1.5-9 and audit-libs-3.1.5-8`
- `python3-audit` 是 3.1.5-9，死认 `audit-libs = 3.1.5-9`
- 系统里的 `audit` 是 3.1.5-8，死认 `audit-libs = 3.1.5-8`
- **同版本的包必须一起升或一起不升**，rpm 不允许同一个库两个版本共存

**第三次**：`audit-libs-python3` 找不到 —— 这其实不是独立包，是 `python3-audit` 的**虚拟 provide**。敲这个包名 dnf 会去下 `python3-audit`，然后提示 `are the same file`。

**结论**：判断"仓库闭包全不全"的唯一可信办法，是**在这台要装的机器上 `--assumeno` 预演一次**，报错消失才算齐。另外有个更省事的工具：

```bash
dnf install --downloadonly --downloaddir=/opt/localrepo mysql-server
```

`--downloadonly` 先完整**模拟一遍安装**（跟 `--assumeno` 同一个算法，**系统状态参与计算**），算出真正要的那批包，再只下不装。它才补得上 `dnf download` 缺的那块。

### 坑 2：加完包不清缓存，等于白干

```
Last metadata expiration check: 0:05:26 ago ...
报错一字不差
```

`repomd.xml` 已经重新生成了，但 **dnf 不会自己去比磁盘上的文件变没变**，它按"多久之前检查过"决定要不要重读，默认 48 小时。所以它压根没看见新加的包。

**往本地源加包的标准三步，缺一不可：**

```bash
dnf download --downloaddir=/opt/localrepo 包名
createrepo_c --update /opt/localrepo     # --update 只处理有变化的文件
dnf clean all                            # 不敲这条，前两条全白做
```

### 坑 3：条件依赖和版本锁，报错要一层层剥

排查顺序不是"看一条改一条"，而是**先把链条完整读出来**：

```
mysql-server
 └─ policycoreutils-python-utils
     └─ python3-policycoreutils
         └─ audit-libs-python3 >= 3.0
             └─ python3-audit 3.1.5-9 要 audit-libs = 3.1.5-9
                  ↑ 而系统里 audit 3.1.5-8 又要求 audit-libs = 3.1.5-8
```

读懂了就知道该补的是 `audit`（主包 3.1.5-9）和 `audit-libs-python3`，而不是去动 `mysql-server`。

### 坑 4：粘贴折行导致命令只执行了一半

```
dnf download --downloaddir=... audit audit-libs-python3
  python3-policycoreutils policycoreutils-python-utils    ← 这行被当成新命令
-bash: python3-policycoreutils: command not found
```

终端把粘贴里的换行当成回车。**看到 `command not found` 先看是不是命令本身没拼全**（D5 的 `tpc port`、D4 的 `fidisk` 是同一类）。太长就用反斜杠续行：

```bash
dnf download --downloaddir=/opt/localrepo \
  python3-policycoreutils policycoreutils-python-utils
```

## 6. 装完的验证（跟 D3、D5 接上）

```bash
rpm -q mysql-server          # → mysql-server-8.0.46-1.el9_8.rocky.0.1.x86_64
systemctl start mysqld       # 成功时**没有任何输出**，沉默就是成功
systemctl status mysqld
systemctl enable mysqld
ss -tlnp | grep 3306
mysql -uroot -e "select version()"
```

`status` 里值得读的：

- `Loaded: ... disabled; preset: disabled` —— 装包不会自动 enable，Rocky 的策略是让你手动开（数据库不该一装就跑起来吃内存）
- `Active: inactive (dead)` —— 进程没在跑，所以 `ss` 抓不到端口，**没输出是正确结果**
- 启动之后 `●` 从空心变实心，`Active: active (running)`，`Main PID: 34640`
- **两个 `ExecStartPre=`**：`mysql-check-socket`、`mysql-prepare-db-dir`，就是"正式启动前先跑预备动作"。D3 手写 unit 只写了 `ExecStart`，这里看到 `ExecStartPre` 的真实用法：**主程序依赖的前置条件交给 systemd 保证顺序**
- 判断真正主进程看 `CGroup` 那棵树（`└─34640`），别被 `Process:` 那几行带偏——那几个是跑完就退的临时进程
- `Status: "Server is operational"` 是 MySQL 主动通知 systemd 的，说明它用的是 `Type=notify`

`ss` 抓到**两个**端口：`3306`（MySQL 经典协议，客户端连这个）+ `33060`（MySQL 8 新增的 X Protocol，给新驱动和文档存储用）。**看到 33060 不是异常**，防火墙只放 3306 就行。

`*:3306` 的 `*` = IPv4 `0.0.0.0` + IPv6 `::`，**监听所有网卡**。跟 D5 那道题对上：数据库绑所有网卡，生产上要改成只听内网。

`systemctl enable mysqld` 输出 `Created symlink /etc/systemd/system/multi-user.target.wants/mysqld.service → ...` ——**enable 的全部动作就是在 `wants/` 下建个软链接**。

`start` 只管这一次，重启就没了；`enable` 管开机。两个是两件事。

公司内网服务器不让上外网，就是自己搭一个这样的内网源，所有机器从它装包。今天第一次亲手做了一遍全流程。

## 8. 面试常问

- "rpm 和 yum/dnf 什么关系" → rpm 是包格式和底层安装器，dnf 是读仓库清单、**算依赖**、下载、再调 rpm 装的前端。`rpm -ivh` 不管依赖，`dnf install` 管。
- "怎么配一个本地 yum 源" → 放包 → `createrepo_c` 生成索引 → 写 `.repo`（`baseurl=file://...`）→ `dnf clean all` → `repolist` 确认
- "装了包但 dnf 说没有 / 版本还是旧的" → 先 `dnf clean all`，本地源还要 `createrepo_c --update`
- "dnf 装不上报 `nothing provides`" → 缺依赖包，`--downloadonly` 在目标机上模拟一遍补全；或者 `--skip-broken` / `--nobest` 权衡
- "`gpgcheck=0` 有什么风险" → 不验签，等于谁往仓库放个包都会被信任

## 9. 欠账

- **第三方源（EPEL）没做**：`dnf install -y epel-release` → 从 EPEL 装一个小工具（比如 `htop`、`ncdu`），验收"第三来源能装东西"。留到下次。

### Q2 的三处问题（同一个命令里）

`chmod 2765 /data/share` → `drwxrwSr-x  root root`

1. **大写 `S` 是错误信号**。setgid 位和"组的 x 位"共用同一个位置：
   - 组有 x → 显示小写 `s`（正常）
   - 组没有 x → 显示大写 `S`（setgid 设了，但组进不去目录）
   - `6` 是 `rw-`，没有 x，所以显示 `S`。**目录没有 x 就不能 cd 进去，也不能在里面建文件**——组员等于被挡在门外。
2. **属组还是 root**。忘了 `chgrp` / `chown`。SGID 只是"新建文件继承目录的组"，**不会自己改目录的组**。
3. 正确的目标是 `2775`（其他人可读）或 `2770`（其他人一律进不来，共享目录更常用）。

```bash
chgrp dev /data/share        # 或 chown root:dev /data/share
chmod 2770 /data/share       # → drwxrws---
```

补充：SGID 目录下**新建的子目录也会自动继承 SGID**，新文件继承的是**组**，不是属主。

### Q3 答案

```bash
echo 'tom ALL=(ALL) NOPASSWD: /usr/bin/id' > /etc/sudoers.d/tom
chmod 440 /etc/sudoers.d/tom
visudo -c
```

- `/etc/sudoers.d/` 下文件名**不能带 `.` 或 `~`**，权限必须 0440，属主 root
- 生产上改 sudoers 一律用 `visudo -f 文件`（它保存时做语法检查）；`visudo -c` 是事后检查
- `NOPASSWD:` 只对**冒号后面列出的命令**免密
- 命令要写**绝对路径**，且 rest of line 是参数匹配：`/usr/bin/systemctl restart nginx` 只放行"重启 nginx"这一条，`systemctl stop nginx` 不行

### Q4 答案

```bash
chage -M 90 -W 7 tom
chage -l tom        # 看结果
```

`-M` 最长有效期，`-W` 提前几天警告。相关文件 `/etc/login.defs`（新建用户的默认值）。
