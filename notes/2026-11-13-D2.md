# 2026-11-13~14 D2 用户与权限

> 格式：问题 → 命令 → 结论/坑

## 做了什么

- **组与用户**：建 `dev` 组、`tom`（主组 dev，家目录、bash），`bob` 从 dev 移除（`gpasswd -d bob dev`），验证 `id tom` 里 dev 在**主组**位置
- **SGID 目录**：`/data/dev` 设为 `drwxrws--- root:dev`；tom 在里面建的文件属组自动是 `dev`；bob 不在 dev 组 → `cd` 被 `Permission denied`
- **sudo 免密**：`/etc/sudoers.d/tom` 写 `tom ALL=(ALL) NOPASSWD: ALL`，`0440 root:root`，`visudo -cf` 通过；`su - tom -c 'sudo -n whoami'` 直接出 `root`
- **账户管理**：锁定/解锁 `passwd -l|-u|-S`；密码策略 `chage -M 90 -W 7`；强制改密 `chage -d 0`；删用户 `userdel` / `userdel -r`；查登录 `lastlog -u` / `last`
- **验收**：新开 `su - tom` 会话，进目录 → 建文件 → 看属组 → `sudo whoami` → 退出，全部通过

## 关键命令

```bash
# 组与用户
groupadd dev
useradd -g dev -m -s /bin/bash tom
gpasswd -d bob dev                 # 从附加组移除

# SGID 目录
mkdir -p /data/dev && chgrp dev /data/dev && chmod 2770 /data/dev

# sudo 免密
echo 'tom ALL=(ALL) NOPASSWD: ALL' > /etc/sudoers.d/tom
chmod 0440 /etc/sudoers.d/tom && chown root:root /etc/sudoers.d/tom
visudo -cf /etc/sudoers.d/tom      # 检查单个文件
visudo -c                          # 检查主文件 + 所有 sudoers.d

# 账户管理
passwd -l|-u|-S user
chage -M 90 -W 7 -d 0 -l user
userdel user / userdel -r user
lastlog -u user / last user
```

## 踩的坑

- **`ls -ld` 不带路径看的是当前目录 `.` 自己**，不是目录里的文件；看文件用 `ls -l 文件名`。我 `chown` 完文件用 `ls -ld` 检查，以为命令没生效。
- **sudoers 文件属主必须是 root**。改成 `tom:dev` 后 sudo 报 `owned by uid 1000, should be 0`，**规则静默失效**。属主 = 提权能力。
- **`chmod 0644` 的 sudoers 文件照样生效**，`0666` 才报 `world writable`。硬规则只有两条：属主 root、不能 world-writable；`0440` 是安全默认值（让普通用户连读都读不了），不是 sudo 的硬要求。
- **`su -tom` 少了空格** → `-tom` 被拆成 `-t -o -m`，报 `invalid option -- 't'`。`-` 必须单独一个参数。
- **`useradd` 在这台机上不写 `-m -s` 也建家目录、用 bash**（`/etc/login.defs` 里 `CREATE_HOME yes`），Ubuntu 不是。别赌默认值。
- **umask 是 0022**，新建文件 `666 & ~022 = 644`、目录 `777 & ~022 = 755`。
- **能 sudo ≠ 身份是 root**：`sudo` 只是一次性借出 root 权限给子进程，`id` 永远是 1000，但**能力等于 root**（能改组、能改 sudoers）。所以生产上必须最小权限。
